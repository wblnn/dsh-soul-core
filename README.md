# dsh-soul-core

给 DeepSeek Harness 的**接管式人格会话**内核：人格存在文件里，每轮重新渲染成系统提示词；记忆走「原始日志 → 事件摘要 → 锚点下钻」的底仓；行为按 preset 分成纯人格 / 带身体 / 工作 / 测试几种模式。

> **它解决什么**：让一个 agent 有「持续的自我」——同一份人格在聊天、游戏、工作里都是同一个人，
> 但上下文预算、工具、记忆域各按场景隔离。原生 Chat 一行不改。

- Node.js ≥ 22，零外部依赖（用内置 `node:sqlite` 与 `zstdDecompressSync`）
- 141 项测试：`npm test`
- MIT

- **不碰 DSH 原生对话**：Chat 的代码一行不改。人格走独立的 agent preset，界面是对话视图环里新加的「人格」标签。
- **接管式**：`@deepseek-ai/dsh-persona` 的 `complete: true`——工作提示词、harness 身份、工具引导全都不进这个会话；`includeRuntimeContext: true`——因为她有真工具了，必须知道沙箱/审批的实时状态。
- **动态**：`dsh-persona` 的 `prefix` 是静态模板，渲染不出"每轮重读文件"，所以这里把内容塞进**提示词变量** `{{soul_block}}`——变量是每次组装求值的函数，改文件立刻生效。
- **有工具但不许闷头干**：注入块里有一段「动手的时候」硬规则（动手前先说、一次一件事、不许连续 3 次工具调用不说人话、改别人代码前说影响面与回滚），同一份也写进了只读的 `RULES.md`。她不是标准模式那个 coding agent，工具只是手。

## 五个模式：本体小，工作模式才给手

| 模式 | preset id | 装了什么 | 人格块 |
|---|---|---|---|
| **人格** | `soul` | 只有 `soul_*`（记忆 / 检索 / 技能） | 2599 字符 |
| **人格 · 我的世界** | `soul-mc` | `soul_*` + `mcc_*` | 4437 字符 |
| **人格 · 工作** | `soul-work` | 全套通用工具：读写 / 检索 / **终端** / 后台任务 / **联网** | 3038 字符 |
| **人格 · 测试（纯聊天）** | `soul-test-chat` | 同「人格」，但不写、不进底仓、不注入本会话历史 | — |
| **人格 · 测试（我的世界）** | `soul-test` | 同「我的世界」，同上 | — |

两个测试模式与对应的正式模式**同构**，区别只有三处：
① 会话不进底仓（preset 不在白名单，写入侧隔离）② 写记忆/技能/日记变成假成功（不改她的行为）
③ 预检索排除本会话。用来反复测同一件事而不污染记忆。

**为什么把手从本体里拿走**：多一个工具 = 多一份 schema + 多一份"我能做这个"的注意力占用。
人格会话要的是"她是谁、记得什么"，不该被 `pwsh` 的参数说明占着。

`handTools` 控制「动手纪律」那段是否注入：本体模式没有手，讲"动手前先说"只会分散注意力；
工作模式才需要它。

工作模式的 `{{soul_block}}` 由一个 `mode: prompt` 的实例提供——**只出提示词变量，不注册任何
`soul_*` 工具**。所以她在工作模式里改不了自己的人格文件，工作内容也不进人格底仓
（`soul-work` 不在 persona 白名单里，从写入侧就隔离了）。

### 问到别的场景怎么办：只给指路牌，不给正文

纯人格模式里被问到「我家门在哪」，她答不上来不是因为懒——**域专项记忆（`MEMORY.mc.md`）和
域技能（`skills/mc/`）根本不在记忆库里**，预检索永远搜不到它们（它们只是磁盘上的文件）。

但也不能把 1000 多字符常驻进去（那就回到吃上下文的老问题）。所以给一行**目录**：

```
## 别处的记忆（不常驻，问到再取）
- mc：专项记忆 → soul_read { name: "MEMORY.mc.md" }；技能 26 条 → skill_recall { query: "…", domain: "mc" }
（这些不在记忆库里，检索搜不到；只在对方问到该场景的事时才去读。）
```

代价 153 字符，换「问了就能给」。三个细节：

1. **只在真有 `soul_*` 工具的模式出现**——工作模式没有 `soul_read`/`skill_recall`，
   给指路牌等于骗她去调不存在的工具。
2. **只列存在的域**：没有 `MEMORY.qq.md` 就不提 qq。
3. 明说「检索搜不到」——否则她会去 `memory_search` 找，找不到就以为没有。

## 装法

```bash
node install.mjs            # 预演：只打印计划，不写任何东西
node install.mjs --apply    # 落盘：建 junction + 往 profile patch 追加 preset 段
node install.mjs --revert --apply   # 回滚
```

装完**重启 DSH**，新建任务时在 preset 选择器里选「人格」。
preset 只对**新会话**生效；已有会话保留原组合（这也是 DSH 的 KV cache 稳定性设计）。

## 人格目录

首次加载在 `~/.dsh/soul/` 播种（幂等，不覆盖已有内容）：

```
IDENTITY.md   我是谁（1200 字符预算）
SOUL.md       声音 / 立场 / 边界（4000）
USER.md       我对你的模型（2500）
MEMORY.md     长期人格记忆（3000，五个维度小节）
RULES.md      硬规则（2000，只读，agent 改不了）
memory/YYYY-MM-DD.md   日笔记（不注入，靠 soul_recall 检索）
```

想换个人格，直接编辑这些文件——不需要重启，下一轮就生效。

## 设置页

设置里有一个**「人格」**区块和一个**「记忆」**区块（都是 `settings.section`，彼此独立），对话视图那边另有一个轻量状态面板（`conversation.view`，和 Chat / Trajectory 并列）。

「人格」能改四件事：

| 区域 | 作用 | 生效 |
|---|---|---|
| 人格目录 | 自我文件放哪儿（留空 = `~/.dsh/soul`） | **重启 DSH** |
| 注入上限 | 每轮人格块的字符预算（默认 11000） | **重启 DSH** |
| 编辑人格文件 | 直接改 5 个文件的内容，保存必填 why | 立刻（下一轮） |
| 提示词预览 | 看 `complete:true` 下真正的唯一系统提示词 | 只读 |

「记忆」管底仓的落点（默认 `<人格目录>/memory-tree`，一个自我一个文件夹）与它的实时统计（会话 / 事件 / 事件骨架 / 帧）。

配置落在 `~/.dsh/soul-core.config.json`（不随人格目录走，否则改完 root 就找不到它了）：

```json
{ "root": "F:\\somewhere\\soul", "memoryRoot": "", "injectBudget": 11000 }
```

生效优先级：**插件 config 参数 > 配置文件 > `$DSH_SOUL_ROOT` / `$DSH_MEMORY_ROOT` > 默认**。
写入前做范围校验（预算必须 500–200000），未知字段直接丢弃。

## 底仓（事件骨架 + 锚点）

**人格库只收人格会话。** 工作会话连索引都不建——不是"标记忽略"，是写入侧直接拒绝。
判定用最后一个 `agent-preset/selected` 事件的 `agentPreset`（`session` 头里的值只是创建时的，
用户可以在会话里切换），默认把 `soul` 视为人格态（`config.personaPresets` 可改）。
中途切换 preset 的会话，只收"当时确实在人格态"的那些事件。

真源永远是 DSH 的 `session.v4.jsonl.zstd`；正文另存一份，但**只存人格会话**的：

```
sessions  一个会话一行（文件、preset、cwd、字节、事件数）
frames    帧级偏移索引 —— 帧只追加 ⇒ (offset,length) 稳定 ⇒ 下钻只解一帧
events    事件索引行（seq/type/time/turn/chars/error），不存正文
messages  全文表：人格会话的正文，按 role 分（user / assistant / reasoning / tool / summary）
episodes  事件骨架：硬边界 + idle gap 切出的区间，带锚点 seq_start..seq_end
episode_notes  事件摘要（强制锚点、版本化）
```

两条实测出来的硬约束：

1. **日志是多帧追加的 zstd**（一个会话 2000+ 帧），`zlib.zstdDecompressSync` 只解第一帧 —— 必须按 magic 逐帧解，否则只能读到 `session` 头。
2. **会话 id 必须取日志 header 的 `id`**，不能靠目录名猜：没有 `session-<id>` 子目录的日志会全部退化成 `session.v4.jsonl`，多份日志挤进同一个 id 后主键互相覆盖、下钻还会解错文件。

断章规则：`compaction/start|end`、`command/run|done`、`agent-preset/selected` 是硬边界；`turn/start` 间隔 ≥ 45 分钟也算断章（实测 10 分钟会把一段连续工作剁成十几段）。已定骨架 append-only，只重算不重切。

摄取是**懒惰 + 时间预算**的：首次访问记忆库时扫一遍 `~/.dsh/sessions`，8 秒预算内能扫多少算多少，下次继续；每次都会顺手清掉库里残留的非人格会话。

## 预检索：不把"查记忆"交给模型主动决定

**只给模型一个 recall 工具 = 最不可靠的设计。** 它手里有工具，但没有任何信号提示"这里有相关记忆"，
于是它不会查，然后凭印象编。所以主入口必须是 Harness 自动做的。

| 入口 | 谁触发 | 负责 |
|---|---|---|
| **预检索** | 每轮组装，**自动** | 「让她看见相关记忆存在」——Top-K 摘要 + 锚点直接进上下文 |
| 下钻工具 | 她主动 | 「摘要不够时读原文」——触发信号是摘要里那句「此处有细节省略」 |

```
当前用户输入（会话日志尾部的最后一条真人消息）
   ↓ cleanQuery：剥掉我们自己的信封【MC 公屏…】与 <玩家名>，避免自己命中自己
   ↓ 检索 searchNotes（摘要）+ searchMessages（原话），score ≥ 2 才收
   ↓ 组装 摘要 + 锚点 + 「此处有细节省略，需要原话就用 memory_expand」
   ↓ 注入 提示词变量 {{soul_prefetch}} → systemPrompt.context（user 侧，不破坏前缀缓存）
```

她看到的是：

```
## 可能相关的记忆（按你刚说的话自动检索：苦力怕炸死的 钻石甲没了）
（不用你主动查——这些是系统替你找出来的；摘要不够再看锚点去翻原文）
- 〔原话·assistant〕被苦力怕炸死了，我在 (157,132,40)，复活在出生点。代价不小：全套钻石甲也没了…　锚点 #10276
```

三个实测踩出来的要点：

1. **必须跳过合成输入**：我们自己注入的聊天/事件摘要也是 `user/message`，拿它当 query 会检索到它自己。
2. **query 要清洗**：`【…】`、`<玩家名>`、`（）` 剥掉再检索，否则全是噪音词。
3. **阈值 ≥2 个词命中**：否则一个常见字就能捞一堆无关摘要，比不注入更糟。

检索目前是**词法**（中文双字切分），零依赖零延迟；换成 embedding + 向量库只需替换 `buildPrefetchBlock` 里那两行检索。

## 注入 · 升降级 · 蒸馏

**注入（读取端）**：人格块末尾会自动追加一小段「最近记得的事」——只有摘要，没有原文。

- 预算独立且很小：最多 1400 字符，且不超过总注入预算的 15%（人格本体优先）
- 每条带锚点，模型可以据此 `memory_expand` 下钻
- 库文件不存在时（首次启动）不去触发摄取，避免拖慢第一轮
- 注入本身记一笔使用信号，但**同一段 6 小时内只记一次**——否则常驻条目会自我强化到永远

**升降级（hot / warm / cold）**：频率只决定注入优先级与保留期，**不决定真值**（底仓在，随时可重建）。

```
score = (下钻 × 5 + 检索命中 × 3 + 注入 × 0.5) × 0.5^(距上次使用天数 / 14)
hot  ≥ 6 且前 3 名   warm ≥ 1.5   cold 其余
```

下钻权重最高，因为「摘要不够用、真去翻了原文」是最强的需求信号。

**蒸馏（提案制）**：`soul_digest` 从人格库全文里抽「反复出现的偏好」与「最近常聊的」，
带出现次数与锚点。**它只出提案，不写文件**——写不写进 `USER.md` / `MEMORY.md` 由模型判断，
写入仍然走 `soul_remember` / `soul_update` 的 why 与预算校验。

## 技能层：在玩里学会技巧

技能是**文件**，不是数据库行：`<人格目录>/skills/<域>/<名字>.md`。

```
skills/mc/挖矿用两格高坑道.md
  ---
  name, domain, trigger, attempts, successes, confidence, evidence, updated_at
  ---
  ## 什么时候用 / ## 步骤 / ## 教训 / ## 实践记录
```

三条硬规则：

1. **evidence 必填**——写清是哪次实践（会话锚点 / 步骤号 / 现象）。没有实践依据的"技巧"就是编。
2. **confidence = 成功次数 / 总次数**，靠真实实践涨落；**失败也要记**（失败比成功值钱）。
3. **注入只给名字 + 何时用 + 置信度**（`skill_read` 看全文），省预算。

### Minecraft：三层分工

`preset-soul-mc` = 同一个人格 + Minecraft 身体：

| 层 | 谁 | 干什么 |
|---|---|---|
| 身体 | `dsh-mc-client` 的 `mcc_*` 工具 | 进服、走、挖、打、吃、捡、被炸了自动复活 |
| 脑子（她） | 本插件 | 想目标、读 `summary.tail[].note`（失败归因）、复盘、说话 |
| 学到的技巧 | `skills/mc/*.md` | 下次动手前 `skill_recall` 查一下 |

学习回路：**玩 → 看结果 → `skill_learn`（带 evidence 与 result）→ 置信度变动 → 下次 `skill_recall` / 自动注入**。

死亡是最有价值的学习点：身体会作废目标并保留死前 `tail`，她该用 `lastDeath.trace` + `tail[].note` 复盘，
把"为什么死"写成一条 `result: failed` 的技能——下次别这么干。

起步技巧用 `node bin/seed-mc-skills.mjs` 从 `dsh-mc-client/docs` 提炼（evidence 标的是文档，
attempts=0、置信 0.30；她真做过一次之后才开始涨）。

### 为什么现在听不见玩家说话（mod 侧要改，插件侧不改）

**输入只有一条：模组 SSE `/events`。插件不读任何本地文件**——不碰游戏目录、不碰服务端日志。
这是硬约束：她将来要进别人的服务器，任何"读本机日志"的取巧都不可接受。

现在的缺口在模组：它只 hook 系统消息。`ChatPacketMixin.java` 的注释写着：

> 玩家普通聊天是另一个包（`ChatMessageS2CPacket`），这里不处理，只要死亡消息就够了。

实测：让身体自己 `chat` 发一句、等服务器回显，`state.chat` 仍是 `[]`。
所以玩家聊天根本进不到 `CHAT_LOG`，SSE 里也不会推 `kind:"chat"`。

**修法（mod 侧，`ChatHudMixin` 加一个重载）**：

```java
@Inject(method = "addMessage(Lnet/minecraft/text/Text;Lnet/minecraft/network/message/MessageSignatureData;Lnet/minecraft/client/gui/hud/MessageIndicator;)V", at = @At("HEAD"))
private void dsh$onAddMessageFull(Text message, MessageSignatureData sig, MessageIndicator indicator, CallbackInfo ci) {
    try { BridgeRunner.onChatMessage(message.getString()); } catch (Throwable ignored) {}
}
```

网络聊天在 1.21.1 走的是 3 参重载（1 参那条只被本地调用），所以补上它就能连玩家聊天一起抓到。
改完 `gradlew build` 重装 jar，桥这边**一行都不用动**——`mc_chat_watch` 会自动开始收到。

### 回合制的她 vs 连续的身体：按级别选通道

她的"想"是**离散回合**（一次完整提示词几千 token），身体的事件是**连续且成簇**的。
这是结构性矛盾，不是调频率能解决的。解法是**按重要性选通道**：

| 级别 | 事件 | 通道 | 延迟 |
|---|---|---|---|
| **P0** | 死亡 / 挨打 / 低血逃 / 岩浆 / 复活 | `followup` 唤醒（**单飞**：15s 内不重复开回合） | 立即 |
| **P1** | 指令被打断 / 目标完成 | **合并窗口 8 秒**后一次性唤醒，带上窗口内全部 | ≤8s |
| **P2** | 常规反射（吃 / 回家 / 丢垃圾 / 停下） | **不唤醒**——写进下一轮 `context`，她下次开口时自然看到 | 下次思考时 |

关键洞察：**P2 的正确通道不是"唤醒"，而是"她下次思考时顺手看到的上下文"**。

### 忙时插话 ≠ 开新回合（这条最容易搞错）

| 她的状态 | 用什么 | 代价 | 时效 |
|---|---|---|---|
| **忙**（回合进行中） | `agent.inject` → 插进**当前回合的下一个 step 边界** | 几乎为零（同一回合多一条消息） | 1.2s 合并窗口 |
| **闲** | `agent.followup` → 开新回合 | 一整个回合 | P0 立刻 / P1 8s |

`inject` 就是"塞进对话图里"——她正在想这件事的时候，下一条就出现在她眼前。
所以**单飞限制只能作用于空闲时的新回合**，绝不能拿来押后忙时的插话
（早期版本这么干过，导致第一条 P0 之后 15 秒内的重要事件全被攒住，失去时效性）。

忙时仍然有 1.2s 合并窗口：同一波里的几条压成一条插话，避免在一个回合中间刷屏。

技术上用提示词变量 + context，而不是塞进 `{{soul_block}}`：

```js
sp.variable("mc_body_events", () => formatEventDigest(MC_CHAT.inbox.take(), { channel: "context" }))
sp.context({ name: "soul:mc_body_events", order: 150, text: "{{mc_body_events}}" })
```

- 变量每次组装求值 → 取走收件箱 → 渲染成 **user 侧上下文**（不是系统提示词）
- 空串会被渲染管线过滤 → 没有待办时它**完全不存在**，零 token
- 不动 `{{soul_block}}` → **不破坏前缀缓存**（人格块一变，整个 prompt 缓存就失效）

两种通道的说法不一样：

```
wake    【MC 身体自己动了 · 最近 9 秒】
        （这些动作你事先不知道，它们发生在你来不及想的时候）

context 【你不在的时候，身体自己做了这些 · 最近 40 秒】
        （这些不用你回，只是让你知道发生过；要改它的反应方式就下 directive）
```

一个要求她处理，一个只要求她知道。混用会让她把"知道"当成"被吩咐"。

### 身体自己动了，她会知道吗

会——但分两种，因为代价不同。

| 事件 | 处理 | 为什么 |
|---|---|---|
| `death` | **立刻转达**，无视冷却 | 死了是"上次决策错了"的唯一硬信号 |
| `reflex`（还手/吃/移动/停下…） | 攒摘要，**≥3 分钟一次**；短窗口攒够 5 条提前 | 10Hz 的反射逐条转达会烧光上下文 |
| `interrupt`（指令被打断） | 进摘要 | — |
| `goal-done` | 冷却过后立刻给 | — |

她收到的长这样：

```
【MC 身体自己动了 · 最近 12 秒】
（这些动作你事先不知道，它们发生在你来不及想的时候）
- 反射：RETALIATE（还手） ×3：hurt(steve)、latch(player)　EAT（吃东西） ×1：food=16,hp=6.2
- 死了 ×1：(96,110,3)，当时有目标，累计第 1 次

想改它怎么反应，就下新的 directive（比如 combat.chase / pickup / 别还手）；不想管就继续做你的事。
```

那句"这些动作你事先不知道"是刻意的：**别让她以为自己做过这些决定**。
反射层存在的意义就是"在你来不及想的时候替你做"，转达时必须保住这个事实。

关掉用 `watchEvents: false`；调间隔用 `reflexCooldownMs` / `burstThreshold`。

### 游戏内聊天当输入通道（像 QQ 群 bot）

`mc_chat_watch` 把公屏接成**常驻输入**：订阅模组 SSE `/events` 里的 `kind:"chat"`。

行为和群 bot 一样：**不需要特意 @ 她**——

- **一直在收**：每条聊天都进环形缓冲（默认 24 条），不管叫不叫她；
- **叫醒时带上下文**：注入的是"最近 5 条"，不是单条。这样她看得懂谁在跟谁说话；
- **两种唤醒**：
  - **点名**（名字 / `@`）→ 立刻醒（3 秒冷却）
  - **氛围**（没人点名）→ 攒够 3 条新消息且距上次唤醒 ≥90 秒 → 叫她一次"要不要接"
- **接不接由她决定**：氛围唤醒的注入文本明说「不想接就什么都别做，这不算失礼」；
- **自己说的进缓冲**：当上下文用（标成 `<我>`），但不触发唤醒。

唤醒时她看到的是：

```
【MC 公屏 · 最近 5 条】
<张三> 走走走挖矿去
<我> 来了
<李四> 等我拿下镐子
<张三> 小鱼快点
（最后一句在叫你。想回就用 mcc_chat 说一句；不接也行。）
```

想临时全听（调试）用 `replyToAll: true, minutes: 2`——两分钟后自动关。

为什么走 `inject/followup` 而不是 `session.append`：后者没被任何回合 claim，前端会把它挂成
输入框上方的"待发送"，不会真的进对话。这是 qqbot 踩过的坑，直接照抄它的入站模式。

她的回话走 `mcc_chat`（身体自带的工具，以她自己账号发出去）。

⚠️ 两个必须知道的边界：

1. **每醒一次 = 一个回合 = 一次完整提示词**。所以节流不是"优化"，是能不能持续玩下去的前提。
2. `mcc_chat` 发出去的话就是她自己账号在公屏说话——**能封号**。别让她自己决定刷屏，
   节流与冷却留在插件这层。

## 联网能力：她不该有

人格会话是"记得的人"，不是"查资料的人"。所以她的 agent scope 里会禁掉联网类全局工具。

做法不是删源文件——那些扩展工具（`expose:'all'`）挂在插件根、对所有通道可见，
删掉会连带把工作会话的搜索能力一起带走。而是用 DSH 原生的 per-agent 限制：

```js
agent.ctx.tools.restrict({ deny: ["bing_search__standard", "web_fetch", ...] })
```

语义正好对：**masks intersect、scoped registrations stay visible**——只影响她那个 agent，
而她自己的 `soul_*` / `memory_*` / `skill_*` 是 scoped 注册，照样可见。

两个封禁时机：

| 时机 | 为什么 |
|---|---|
| **提示词组装**（每轮都发生） | 早于任何工具调用，堵住「开局第一件事就搜索」的窗口 |
| 工具调用兜底 | 万一认不出 agent 的 preset，第一次调工具时补刀 |

匹配规则：`/(bing|web|search|crawl|fetch|browse)/i`，但**排除我们自己的名字**
（`memory_search` / `skill_recall` 都带 search 味道，不能被误封）。
需要额外禁别的工具时用 `config.denyTools: ["qq_send__standard"]`。

只封 `preset ∈ {soul, soul-mc, soul-qq}` 的会话——**标准模式（工作会话）不受影响**，这点有测试钉着。

`MEMORY.md` 是**每轮都注入**的，所以它只能放跨场景的稳定事实。MC 里的"家在这、别乱挖"、
"公屏叫醒要用 mcc_chat 回"这类只在游戏里有意义的规则塞进去，要付两份代价：
吃掉所有场景的预算，还在聊天场景里制造噪音。

所以有第二层：`MEMORY.<域>.md`（如 `MEMORY.mc.md`），**只在那个域的 preset 里注入**。

| 文件 | 注入范围 | 预算 |
|---|---|---|
| `MEMORY.md` | 所有场景 | 3000 |
| `MEMORY.mc.md` | 只有「人格 · 我的世界」 | 2000 |
| `MEMORY.qq.md` | 只有群聊场景 | 2000 |

`soul_remember` 按当前域自动路由：MC 场景里写的进 `MEMORY.mc.md`，聊天场景里写的进 `MEMORY.md`；
她会从工具返回里看到写到了哪个文件。

注入块长这样（只出现在 MC 场景）：

```
## mc 专项记忆（只在这个场景注入，别处看不到）
## 对话里的事
- （2026-10-29）家的门在 (86,104,3)；樱花木压力板 (86,104,2) 那一侧是屋里…
```

跨场景仍然共享的是 **认人**（`people.json`）与**经历**（事件摘要），不是 `MEMORY.md`。

## 跨场景：一个库，不割裂

MC、QQ 群、纯聊天——**同一个 `memory.db`**，`preset` 只是标签，不是分库：

| preset | venue 标签 | 说明 |
|---|---|---|
| `soul` | `chat` | 纯对话 |
| `soul-mc` | `mc` | 在游戏里（含公屏聊天的注入记录） |
| `soul-qq` | `qq` | 在群里 |

- 检索与注入**跨场景共享**：在群里问"上次挖矿那事"，她能捞到 MC 的经历。
- 同场景记忆在排序上乘 **1.25** 轻加权——只是让当下的场景略微靠前，**不排除别的场景**。
- **技能是分域的**（故意的）：挖矿技巧在群里没意义。技能走 `skills/<域>/`，记忆走一个库。

### 「人」的跨场景身份

记忆共享了，还得**认人**：MC 里的 `张三` 和群里的 `qq昵称` 是同一个人。
`person_link` 把名字挂到同一个键上，落在 `<人格目录>/people.json`：

```json
{ "主人": { "mc": ["张三"], "qq": ["qq昵称"], "note": "他本人" } }
```

注入时压成一行：

```
## 人（同一个人在不同地方的名字）
- 主人（他本人） — MC：张三｜QQ：qq昵称
```

MC 公屏进来时也会先反查：`【MC 游戏内聊天｜主人（MC:张三）】…`，
于是她不会把同一个人当成两个陌生人。

### 注入顺序与预算

```
人格本体 → 〔你现在在哪〕→ 〔人〕→ 〔最近记得的事〕→ 〔你学过的技巧〕
```

后四块合计吃掉总注入预算的 **30%**（人格本体优先），超了按顺序截断。

## 给别的插件复用

人格内核是**纯模块 + 磁盘状态**，不是 cordis 服务（避开 preset scope 的"服务泄漏"审计）：

```js
import { renderBlock, remember, recall, status } from "dsh-soul-core/persona-api";
```

QQ 机器人、桌宠、角色扮演 agent 都可以读同一份 `~/.dsh/soul/`——共享的是磁盘上的自我，不是内存里的单例。

## 两个必须知道的技术细节

1. **花括号会被中和**：DSH 的提示词插值器把 `{{name}}` 当变量引用，未知引用直接抛错、整个组装失败。人格文件是自由编辑的，所以渲染时会在相邻花括号之间插一个零宽空格（U+200B）：肉眼无变化、内容零丢失、但永远不会拼出 `{{`。
2. **人格块永远不为空**：空系统提示词会让 DSH 清掉所有系统节点，所以渲染失败时返回兜底文本，绝不返回空串。

## 排查

宿主进程的 stdout 拿不到，所以插件把关键步骤写进 `~/.dsh/soul/soul-core.log`：

```
apply() root=... mode=-
mountVariable done
mountRoutes done
mountTools done: 6 tools, defineTool=local
```

**工具不生效时先看这个文件**：`mountTools done` 说明注册成功；若只有 `mountVariable done`，
说明挂在了工具那一步。

### 踩过的两个坑（已修，留档）

1. **`await import("@deepseek-ai/dsh-tools")` 在宿主进程里会挂住**。`apply` 因此永远走不到
   工具注册那一步——现象极有迷惑性：人格块正常注入、对话正常，但 `soul_status` 一调就是
   `UNKNOWN_TOOL`。修法：`apply` 改成**全程同步**，`defineTool` 只用本地实现，
   工具注册放在任何异步操作之前。
2. **不要用 PowerShell `Set-Content` 改这些文件**。PS 5.1 默认按 ANSI 写，会把中文写成乱码、
   还能把引号吃掉导致语法错误（本项目的测试文件就被这么毁过一次）。改文件用编辑器或
   `[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`。

## 自动回绝的护栏（MC 公屏）

她会用**自己的账号**在公屏说话，所以这条路径按封号风险对待：

- **必须被点名**：名字命中或带 `@` 才回。不点名就插嘴 = 公屏上任何一句「帮我写个脚本」她都要怼。
- **节流**：同一账号 30 秒冷却 + 每小时最多 6 次（`gateCooldownMs` / `gateMaxPerWindow`）。
- **宁可漏判**：判定要求「技术对象 + 派活动词 + 不是自述」三者同时成立；光有动词不算（「我修了个房子」也是修）。漏判的代价是她照常用模型回答，误判的代价是她无故怼人。
- 任何一条不满足都**落回正常流程**，不做提前返回。

## 已知风险

- `prefix: '{{soul_block}}'` 是硬依赖：本插件若加载失败，变量就不存在，那个人格 preset 的每次请求都会在组装阶段抛错（但会明确报错，不会静默变傻）。工作会话不受影响。
- `soul_*` 工具固定用 `lib/define-tool.js` 的本地实现。`ctx.tools.register()` 只强制校验 `output.{schema,render}` 与名称保留字，本地实现满足；不依赖 `@deepseek-ai/dsh-tools`（本机 profile 里那些 `@deepseek-ai/*` 是指向旧安装路径的失效 junction）。
- `includeRuntimeContext: false` 是官方语义上的"全有或全无"：沙箱策略、审批策略、委派上下文一起关掉。人格会话零工具，没有需要审批的操作，所以这个取舍可接受——但**不要往这个 preset 里加会动手的工具**。

## 底仓摄取是增量的（底仓不该落后现场）

三个数字说明为什么：

| 做法 | 一个 10.5 MB 会话 | 51 个会话一轮 |
|---|---|---|
| 整篇解码（旧实现） | 1083 ms | ~2000 ms |
| 只解新增帧（现在） | 1 ms | ~10 ms（稳态） |

- 文件没变 → 只比字节数就跳过，**不解码**
- 文件变大 → 从上一帧末尾往后读，只解新帧（帧是只追加的，`(offset,length)` 永远有效）
- 不是人格会话 → 先用「开头 64 KB + 尾部 256 KB」探针判定，**不解全文**，并按 `(文件, 尺寸)` 记住
- 后台每 20 秒跑一次（`ingestEveryMs`），所以「A 会话说的事」在 B 会话里最多 20 秒可见

## 跨会话简报（换个会话接着聊）

预检索是**词法**的：A 里说「钥匙放鞋柜了」，B 里问「那东西在哪」一个词都对不上。
所以另有一条不依赖命中的路：把**别的会话**最近 12 小时的原话接进 context
（默认 600 字符、最多 3 个会话，`recentHours` / `recentBudget` 可调）。
测试模式不注入——测试要的是干净上下文。
